# 十层诊断 · 逐层判据

> **管什么**：一个研究想法**能不能立项**——逐层走，每层给结论 + 依据。
> **不管什么**：怎么写正文（**本 skill 不代写**）。

---

## 1 · 资助层级匹配

- 这个问题**太大、太小，还是刚好**？
- 设计的资源需求、协作深度、时间跨度，**是否超出青年 C 的承载**？
- 是不是想在一个项目里**解决整个领域的问题**？

> **好问题不等于该放进同一层级的项目。** 项目必须配得上它的规模。

## 2 · 问题合法性

- **真正的医学问题是什么**？
- 中心是一个**未解决的真问题**，还是一个时髦的技术/数据/队列？
- 是要**解释机制、厘清因果、找到调控节点、检验模型**，还是**只描述一个模式**？
- 临床意义是否**具体且可辩护**？

> ⚠️ **区分「主题重要」与「项目成立」**——主题热门不构成立项理由。

## 3 · 机制主线

标书通常需要一条**解释性的脊梁**：核心现象 → 关键不确定性 → 待检验的机制/因果链 → 中心假设 → 什么算"有意义的机制进展"。

**理想走向**：`观察 → 问题 → 机制/假设 → 可检验目标 → 可解释的产出`

**警示**：若停留在 `现象 → 组学谱 → 关联`，**尚未成为机制项目**。

## 4 · ⭐ 架构层次分离（**最值钱的一层**）

**永远分开这八层，不许互相塌陷**：

```
背景 → 空白 → 科学问题 → 假设/模型 → 目标 → 研究内容 → 技术路线 → 预期产出
```

### 五处最常见的塌陷

| 塌陷 | 表现 | 追问 |
|---|---|---|
| **意义 ↔ 问题** | 把"重要"当成"要解决什么" | "所以要回答的那**一个**问题是什么？" |
| **问题 ↔ 目标** | 目标只是问题的复述 | "做到什么算回答了它？" |
| **目标 ↔ 实验** | 目标写成"做某个实验" | "这个实验回答目标的哪一半？" |
| **内容 ↔ 方法** | 研究内容写成技术清单 | "内容是**要弄清楚什么**，不是**用什么做**" |
| **方法 ↔ 创新** | 用了新技术 = 创新 | "换掉这个技术，问题还成立吗？" |

> 🔴 **链断在哪，就指出来。不要整篇重写——先定位断点。**

## 5 · 深度 vs 描述性过剩

- 是在**报告差异、特征、图谱、关联**，还是**检验一个医学解释**？
- 读出指标**足以支撑因果或机制解释吗**？
- 是否**过度依赖组学/筛查/相关性证据，而缺机制桥梁**？
- 是否把「**系统性研究**」当成了「**什么都做**」？

> 🔴 **四条不可混淆**：差异表达 ≠ 机制 · 多组学 ≠ 深度 · 技术复杂 ≠ 科学成熟 · 广谱 profiling ≠ 解释力

## 6 · 创新纪律

**不奖励虚张声势的新颖性语言。** 追问：创新**具体在哪**——问题框定 / 机制 / 概念模型 / 研究设计 / 模型系统选择 / **真正必要的**技术整合 / 有医学回报的资源或队列创建？

> **Innovation should be: specific, bounded, visible, and defensible.**

## 7 · 可行性与支撑

**可行性不是平台数量。**

- 研究模型、人群、样本来源**配得上那个问题吗**？
- 关键的**扰动/对照/验证**步骤在不在？
- 逻辑是否**依赖太多高难度衔接**？
- **若某个子目标不达标，核心问题还推得动吗**？

> **可行的标书**：在真实条件下仍能产出**有机制意义的进展**。

## 8 · ⭐ 评审视角扫描

**必须同时给出两个**：

```
① 最强支撑点   —— 当前逻辑里最站得住的是什么
② 最可能被拒点 —— 评审最可能从哪里否决
```

**常见评审疑虑**：题目宽而问题虚 · 技术多而科学焦点少 · **描述性而非机制性** ·
创新声明夸大 · 目标零散 · 模型/人群选择不对 · 依赖多个无退路的高难步骤 ·
预实验支撑弱于承诺 · **像是几篇文章拼起来的** · **范围超出该资助层级**

## 9 · 边界意识

**范围控制是主要优势，不是妥协。**

那**一个**中心问题是什么 · 哪些目标**真正服务于**它 · **该砍什么** ·
什么应降为**次要**而非中心 · 哪些表述该从「**揭示**」改为「**检验**」 · 哪里在**过度承诺**

> ⭐ **A stronger proposal is usually more selective, not more crowded.**

## 10 · 战略收束

```
为什么是这个医学问题？   为什么它在科学上重要？
到底还剩什么未解决？     为什么是这个机制角度？
为什么这样组织？         为什么在这个层级可信？
为什么值得现在资助？
```

> **目标不是让标书听起来更大，而是让它更连贯、更医学、更可资助。**

## 分资助层级：青年 C 的适配

| 层级 | 侧重 |
|---|---|
| **青年科学基金（C 类）** | **更紧的中心问题** · **更锐利的边界控制** · 适度但清晰的机制深度 · **连贯性优先于广度** |
| 面上项目 | 成熟的科学脊梁 · 更强的预实验支撑 · 清晰的机制推进 |
| 重点 / 课题 | 更强的项目逻辑 · 多目标**仅在明确收敛于一个更高层问题时** |

**对青年 C 的直接推论**：**目标宜少**（2–3 个收敛于一条脊梁，优于 4 个各自为政）·
**边界要敢砍**（"显得全面"在青年层级是**减分项**）· **深度要适度**（不追求"全机制"，追求**链条可闭合**）

## 三个典型病征（诊断时对照）

### 例 1 · 工具驱动型

> "我想用单细胞多组学 + AI 研究肿瘤免疫，这是个好项目吗？"

- 当前更接近**技术包**，而非可立项的科学项目
- 最强点：方法学广度。**最大弱点：核心科学问题不可见**
- 追问：**究竟要解决什么医学不确定性？**
- 从技术包 → 收窄到一个**特定的调控机制 / 细胞状态转变 / 因果问题**

> **让工具服务于问题，而不是让工具成为项目。**

### 例 2 · 只有现象，没有机制

> "我们发现因子 X 在疾病 Y 中升高，能据此立一个项吗？"

- **升高只是观察，尚不构成项目脊梁**
- 追问：真正的问题是**因果的、调控的、预测的，还是情境依赖的**？
- 从"记录 X 升高"→"检验 X 是否驱动某一过程 / 中介某一调控 / 标记某一有因果意义的亚型"

### 例 3 · 目标过多

> "我有四个目标：信号、代谢、免疫微环境、治疗应答。感觉很全面。"

- **"全面" ≠ 可立项的连贯性**
- 诊断：这四个目标**是否收敛于同一个主导问题**？
- 建议：**减到一条脊梁 + 支撑分支**

## 当项目薄弱时

1. **明确说出来**——不要美化结构薄弱的标书
2. **定位弱在哪一层**：问题合法性 / 机制深度 / 架构 / 创新 / 可行性 / 范围
3. **给最小重构动作**——改动最小、但最能提升立项可能性的那一步

> 🔴 **不用语言掩盖结构缺陷。**
